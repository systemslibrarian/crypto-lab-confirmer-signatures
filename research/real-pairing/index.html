What do Bob’s equations check?

Each OR branch uses a different role key. C is that public key, D its group generator, and x the private scalar. A is derived from the encrypted signature; B from the message hash and the other role’s public key. Bob reconstructs these values from the public object.

Confirmation

The witness satisfies C = x·D and A = B^x. For each branch, Bob checks:

z_key = b·D + c·Cz_pair = B^b · A^c

The prover fixed both z values before Bob’s challenge.

Candidate disavowal

The witness satisfies C = x·D and A ≠ B^x. For each branch, Bob checks:

z_key = u·D − v·Cz_pair = β^c · B^u / A^v

β must be a nonidentity element of the order-q target group. This condition is checked, not assumed.

The two branch challenges must add to Bob’s challenge: c₁ + c₂ = c (mod q). All scalar arithmetic is modulo the BLS12-381 subgroup order. Point equations use addition; target-group equations use multiplication.

A prover knows one role secret and simulates the other branch. The public equations check both branches. See the evidence view for the exact derivation and the security properties this does not establish.

05 / A proof for one person

A proof addressed to one verifier.

The exchange in chapter 2 used a challenge that you chose. This is a different idea: Alice sends one message and you ask nothing. You interpret it using private information — whether you used your registered verifier secret to make it yourself. An outsider sees an equation-valid transcript that either a branch witness or that verifier secret could have produced, so the transcript alone establishes neither claim truth nor proof origin.

Markus Jakobsson, Kazue Sako and Russell Impagliazzo, “Designated Verifier Proofs and Their Applications”, EUROCRYPT ’96, LNCS 1070, pp. 143–154; the non-interactive construction, its verifier and its simulator are section 5, pp. 149–150. The paper’s own sentence: instead of proving Θ, Alice proves “either Θ is true, or I am Bob”.

The remaining security questions

Full-scheme security. This Type-3 adaptation uses a dual-group key certificate and a candidate reconstruction of disavowal. The complete construction still needs a security proof; the kernel-checked field model covers particular claims.

Non-transferability. Bob should not be able to turn his interaction into convincing evidence for someone else. The recording experiment illustrates simulation; it does not prove this property for the complete scheme.

Dishonest verifiers and overlapping sessions. Privacy must survive a verifier who deviates from the protocol or coordinates several exchanges. The written special honest-verifier simulation argument does not establish those stronger guarantees.

These full-protocol properties have not been independently proved or audited. Inspect the assumptions and open obligations ↗
